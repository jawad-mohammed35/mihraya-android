# Mihraya 1.8.0 QA

Verified November 17, 2026. Version code 12. Android 15/API 35 x86_64 emulator, 1080×2400 at 420 dpi. No physical device or older-Android testing was performed.

## Names typography and UI

- All characters used by all 99 Names are covered by each selected bundled font: Amiri 1.002, Noto Naskh 2.021, Noto Nastaliq Urdu 3.009. The underlying Names JSON is byte-identical to the previous commit. No text replacement, Quran dataset substitution, mark removal, or manual glyph positioning was done.
- Inspected the list and popup in Amiri, Noto Naskh and Nastaliq. The preference is stored independently in the existing More-tools preferences and observed by both the reader and learning screens. A signed-app cold restart retained Nastaliq. Existing Zakat values and learning progress survived adding the preference in isolated Android tests.
- Arabic uses RTL direction, normal weight, zero tracking and font padding. The selected line-height factors exceed each font's hhea span (Amiri 1.9 vs 1.758 em; Naskh 1.9 vs 1.703; Nastaliq 2.6 vs 2.5). Coverage/metric results are recorded in `docs/names-font-audit.json`. These checks and visual samples do not constitute an exhaustive expert review of every glyph on every Android shaper.
- The long Name 85 popup was exercised with 1.5× font scaling and 320 dp content width. Controls remained scrollable. Search, copy/share intent and both learning games remained functional. Tests covered all themes and accents through the existing theme implementation.
- Learn remains in its original position. The source/description block beneath it is absent; the new font selector occupies that area. Names attribution remains in About, NOTICE and shared text. Existing OFL and source licences remain intact.
- Screenshot previews were inconsistent on the emulator, including system status text. Native saved-PNG pixel inspection confirmed opaque label pixels, and a new Compose pixel test verifies that the Copy label is painted rather than merely present in semantics. A cold software-rendered session and focused UI tests were also used. The existing button animations were retained; no speculative rendering redesign was shipped.

## Zakat

- The annual estimate shows the amount prominently, with a dash for incomplete/invalid input and concise Hawl/Nisab status where necessary. The introductory explanation and complete visible Guidance & Sources card are removed.
- Relevant metal-price, purity, investment, deduction and Hawl assumptions remain beside their controls. Islamic Relief/Gold API attribution and the ounce-to-gram conversion are retained in About; share summaries retain their assumptions/disclaimer.
- `ZakatCalculator.kt` is unchanged. Existing tests cover every asset category, deductions, exact/below Nisab, gold/silver standards, Hawl, zero/negative wealth, missing/invalid prices, large values, units, purity, jewelry and rounding. The Android test verifies $1,000 of cash at silver $1/g with Hawl confirmed gives $25, including the new top summary, save/reset/load and absence of the removed guidance text.

## Hadith source audit

- Audited the authenticated HadithAPI book/chapter endpoints and every page for seven populated source editions: Bukhari 7,276; Muslim 7,564; Tirmidhi 3,956; Abu Dawud 5,274; Ibn Majah 4,341; Nasa'i 5,761; Mishkat 6,293. The seven snapshots contain all 40,465 records reported by this provider, with nonempty Arabic, unique IDs/numbers, matching chapter metadata/counts, and no Unicode replacement characters in the texts or chapter titles checked.
- `chapterId` in a narration is the source book-local chapter number; it was checked against both nested chapter metadata and the chapters endpoint. Muslim's chapter-zero introduction is preserved. Arabic titles, per-record headings, narrator fields and source numbering/volume are retained without guessed relationships or grading.
- Missing English remains explicit: Bukhari 2 records, Tirmidhi 7, Nasa'i 2; Mishkat has no English. No Arabic record was deleted to conceal a translation gap, and no placeholder or machine-generated translation was inserted. Six complete Urdu editions are offered; Tirmidhi's incomplete Urdu is omitted. Provider status labels identify HadithAPI and the absence of a named grader.
- The three existing editions remain bundled and unchanged. The catalogue contains 10 collections without duplicate collection/language keys. Thirteen new gzip packages total 28,065,822 download bytes and do not ship in the APK. Exact source/package digests and exception IDs are in the two HadithAPI audit JSON files.
- This establishes agreement with the selected source snapshots, not scholarly textual/translation/grading verification or canonical completeness across other editions. Musnad Ahmad/Al-Silsila Sahiha report zero records; Muwatta/Darimi/Riyad/Bulugh/Al-Adab are absent from this API. No empty collection cards or speculative repairs were added.

## Automated and storage checks

Full command: `./gradlew :app:testDebugUnitTest :app:connectedDebugAndroidTest :app:lintDebug :app:assembleRelease -PhadithPackageQa=true -Pandroid.injected.androidTest.leaveApksInstalledAfterRun=true`

- 70 JVM tests passed. All 15 Android tests passed with generated fixtures present and no skips. A subsequent focused run of all 11 More UI tests passed with the original button animations and rendered-label pixel check.
- Every one of the 13 new compressed packages was imported through the real Android repository with a deterministic transport supplying exact pinned bytes. Checks covered chapter counts, Arabic titles, source records/headings, language switching, missing-translation flags, English fallback, random-ID validity/no repeats, bookmarks, corruption/truncation rejection and removal. Old French/plain-JSONL regressions also passed.
- The version-1-to-2 content migration retained all original Nawawi rows and separately stored bookmarks, language, font size and reading anchor while building the search index. No user-store schema was replaced. The signed update was installed over 1.7.0 without uninstalling/clearing data; settings.json, library.json, hadith-user.json and more_tools_v1.xml were byte-identical immediately after upgrade. Subsequent font-selection QA intentionally changed only the new font preference.
- The full-package run measured 87,191 ms for importing all 13 editions and 40 ms for two bounded searches on a warm emulator database. These are observations, not device-independent performance guarantees or frame-time benchmarks. Result pages are bounded and source parsing/decompression is streamed.
- Removing an edition now uses incremental page reclamation instead of rewriting the entire expanded cache. The one-time conversion of the previous small database retains its rows. Gzip size, SHA-256, expanded-byte bounds, line size, translation coverage and transaction rollback are enforced.
- Lint: zero errors, 87 existing/dependency/platform warnings. The signed minified build passed; APK v2 signature and ZIP alignment were verified with build-tools 36.0.0. The original signing certificate remains in use.

## Credential and rights checks

- The credential was read only from the ignored local file. No runtime backend/API secret is needed by the app: authenticated import is local, and phones download static allowlisted packages. Pagination URLs are discarded; redirects are constrained to the provider's HTTPS origins and errors suppress request URLs/keys.
- Exact credential scans found no match in publishable source, Git history, all 13 decompressed packages, or the release APK entries. The `.secrets` directory and source caches are excluded from Git and app assets. No credential was printed in a request/error log.
- HadithAPI's free-access statement was reviewed, and the owner explicitly authorized offline use. Public request-rate limits and explicit bulk/offline redistribution rights were not found. No independent translator/publisher rights clearance is claimed. These limits and provider attribution remain in NOTICE, README and edition credits; Apache 2.0 remains unchanged for Mihraya's own code.

## Limits

No physical device, older API, long-duration interruption/process-death matrix, exhaustive prayer-alarm/audio/widget regression, or independent scholarly/legal audit was performed. Existing automated regressions were retained. Public release-asset transport is checked after publication and recorded in the follow-up. The emulator had an unrelated Bluetooth system-process crash; no Mihraya crash was observed during the signed-app checks.
